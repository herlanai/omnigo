# Verified artifact downloads

`Get(ctx, File{URL, SHA256, Size, ...}, path)` downloads into a private file beside the destination, checks the byte limit and SHA-256, syncs and atomically renames it. Failure leaves an existing destination intact. SHA-256 is mandatory; unknown sizes are bounded to 64 MiB by default, configurable to at most 4 GiB. HTTPS and loopback HTTP are supported; redirects cannot change scheme or bypass the URL policy. Transient HTTP/transport failures retry with bounded exponential delays; cancellation interrupts delays and reads. Progress executes synchronously on the caller's goroutine, so UI consumers must dispatch updates.

`Cached` uses flock on macOS/Linux and LockFileEx on Windows to serialize cooperating processes, rechecks the hash under the lock, and downloads once. The advisory lock file remains in place to avoid splitting waiters across different inodes. OS locks release when a process closes/exits. Cache directories must be application-owned; this is not an adversarial shared-directory protocol. Files default to mode 0600; executable artifacts must explicitly request 0755. A successful publication does not promise directory fsync/crash durability or replacement of in-use Windows libraries.

The updater plugin uses this downloader after its existing signed-manifest verification. Tests cover retries, hash failure, size budgets, cleanup, cancellation, existing-file preservation, two clients and two actual processes sharing one download. No code executes or installs the downloaded artifact. Full update/delta/installer/native-plugin management remains separate work.
